# 🌿 Природні Мандри — Frontend

Це фронтенд-частина платформи **Природні Мандри**, розроблена для популяризації
еко-туризму в Україні. Проєкт побудований на **Next.js** з акцентом на
продуктивність, доступність та mobile-first підхід.

---

## 🛠 Технологічний стек

Проєкт використовує сучасні інструменти, що забезпечують стабільність та
швидкість MVP:

### 🌐 Core

- **[Next.js 16 (App Router)](https://nextjs.org/docs)** — основний фреймворк.

- **[React 19](https://react.dev/)** — бібліотека інтерфейсів.

- **[TypeScript](https://www.typescriptlang.org/)** — сувора типізація.

### 🎨 Стилізація та UI

- **CSS Modules** — ізольовані стилі для кожного компонента.

- **[modern-normalize](https://github.com/sindresorhus/modern-normalize)** —
  скидання стандартних стилів браузера.

- **[Swiper.js](https://swiperjs.com/)** — реалізація слайдерів для популярних
  статей та мандрівників.

- **[clsx](https://www.npmjs.com/package/clsx)** — Для динамічного керування
  класами.
- **[React Hot Toast](https://react-hot-toast.com/)** — легкі та гнучкі
  індикатори успіху/помилок (toast-повідомлення).

### ⚙️ Керування даними

- **[TanStack Query](https://tanstack.com/query/latest)** — синхронізація
  серверного стану та кешування.

- **[Axios](https://axios-http.com/docs/intro)** — HTTP-клієнт для взаємодії з
  API.

- **[Zustand](https://zustand.docs.pmnd.rs/learn/getting-started/introduction)**
  — легкий менеджер глобального стану (авторизація, модальні вікна).

### 📝 Форми

- **[Formik](https://formik.org/docs/overview)** — керування станом форм.

- **[Yup](https://www.npmjs.com/package/yup)** — валідація даних на клієнті.

- **[React Dropzone](https://react-dropzone.js.org/)** — реалізація поля для
  завантаження зображень обкладинки статті.

## 🛠 Командний Workflow

### 1. Стилізація (CSS Modules)

- Кожен компонент має свій файл `Name.module.css`.

- Використовуйте змінні з `:root` для консистентності.

## 2. Взаємодія з API

Усі запити виконуються через **Axios**.

- Налаштований інстанс знаходиться в `lib/api.ts`.

- Усі запити мають проходити через сервісний шар у `lib/api/`. Заборонено
  викликати Axios напряму всередині компонентів.

| Інстанс     | Де використовувати  | Особливості                                                                                                                                        |
| ----------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `clientApi` | `Client Components` | Працює через браузер. Використовує `httpOnly cookies` (автоматично передаються браузером), не потребує ручного керування токенами.                 |
| `serverApi` | `Server Components` | Використовується на стороні сервера. Потребує ручної передачі кук з контексту Next.js (`headers/cookies`) для авторизації запитів "сервер-сервер". |

### 3. Правила Server/Client Components

- **Server Components:** Використовуємо за замовчуванням для сторінок та
  статичних частин.

- **Client Components:** Тільки там, де є `useState`, `useEffect`, `Formik` або
  `Swiper`. Додаємо директиву `'use client'` на рівні найменшого можливого
  вузла.

### 4. Робота з гілками та комітами

Використовуємо стандарт Conventional Commits:

- Використовуємо стандарт **Conventional Commits**:
  - `feat: ...` — нова функціональність.
  - `fix: ...` — виправлення помилки.
  - `docs: ...` — зміни в документації.
  - `refactor: ...` — зміни коду, які не виправляють помилку і не додають фічу
    (покращення структури).
  - `style: ... —` правки, що не впливають на логіку (відступи, форматування,
    лапки — те, що робить Prettier).
  - `perf: ... —` зміни для покращення продуктивності (наприклад, оптимізація
    рендеру списку товарів).
  - `test: ... —` додавання нових тестів або виправлення існуючих (Jest/E2E).
  - `build: ... —` зміни, що впливають на систему збірки або зовнішні залежності
    (пакети в package.json, конфіг Next.js).
  - `ci: ... —` зміни в налаштуваннях CI/CD (GitHub Actions, скрипти
    автоматизації).
  - `chore: ... —` iнші дрібні зміни, які не стосуються коду чи тестів
    (наприклад, оновлення .gitignore).

## ✅ Чек-лист перед Pull Request:

- [ ] **Відсутність `any`**: Весь код має бути суворо типізований.
- [ ] **Conventional Commits**: Назва PR та комітів відповідає стандарту.
- [ ] **Форматування**: Виконано команду `npm run format`.
- [ ] **Чистота консолі**: Видалені всі `console.log`, `debugger` та
      закоментовані шматки коду.
- [ ] **Відсутність помилок**: Команда `npm run lint` проходить без попереджень
      та помилок.
- [ ] **Environment Variables**: Якщо додано нові змінні оточення, вони
      задокументовані в `.env.example`.

> **Порада:** Якщо ваш PR містить зміни в інтерфейсі (UI), будь ласка, додайте
> скріншот або запис екрана (Loom/GIF), щоб пришвидшити процес перевірки для
> колег.

## 🚀 Як почати роботу

Дотримуйтесь цієї послідовності для локального запуску фронтенд-частини:

### 1. Підготовка та встановлення

```bash
# Клонування репозиторію
git clone https://github.com/OksanaVakuliak/pryrodni-mandry-front.git

# Перехід у папку проєкту
cd pryrodni-mandry-front

# Встановлення всіх залежностей
npm install
```

### 2. Налаштування середовища

```text
NEXT_PUBLIC_API_URL=http://localhost:3000/api
```

### 3. Запуск сервера розробки

```bash
# Запуск Next.js у режимі розробки
npm run dev
```

## 🛠 Додаткові команди для розробки

| Команда                | Що робить                                                                      |
| ---------------------- | ------------------------------------------------------------------------------ |
| `npm run dev`          | Запускає сервер розробки на http://localhost:3000.                             |
| `npm run format`       | Автоматично виправляє відступи та стиль коду (Prettier) у файлах ts, tsx, css. |
| `npm run format:check` | Перевіряє, чи відповідає код правилам форматування (без виправлення).          |
| `npm run type-check`   | Перевіряє весь проєкт на помилки TypeScript (без збірки).                      |
| `npm run lint`         | Запускає перевірку лінтером ESLint.                                            |
| `npm run lint:fix`     | Автоматично виправляє прості помилки лінтера.                                  |
| `npm run build`        | Створює оптимізовану збірку проєкту для продакшну.                             |
