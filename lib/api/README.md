# 🌍 API Layer Documentation

Ця папка містить логіку взаємодії з бекендом. Ми використовуємо **Axios** як
основний клієнт та архітектуру, що розділяє клієнтські та серверні запити.

## 🏗️ Архітектурний принцип (Proxy)

**Важливо:** Ми не робимо запити з компонентів або сервісів напряму на зовнішній
URL бекенда. Всі запити йдуть на **Next.js Route Handlers** (папка `app/api/*`).

**Чому так?**

1. **Безпека**: Приховування справжньої адреси бекенда.
2. **CORS**: Уникнення проблем із крос-доменними запитами.
3. **Cookies**: Зручне керування сесіями та HTTP-only cookies на стороні сервера
   Next.js.

---

## 🛠️ Основні файли

### 1. `api.ts` (Base Instance)

Основа для всіх запитів. Тут налаштований базовий URL та заголовки. Це
**"чистий"** клієнт Axios.

- **Конфігурація**: Використовує `withCredentials: true`, що є критично важливим
  для автоматичної передачі **HTTP-only cookies** між браузером та сервером.

### 2. `clientApi.ts` (Client-Side Requests)

Використовується виключно в **Client Components** або клієнтських хуках.

- **Безпека (HTTP-only)**: Цей файл **не використовує interceptors** для
  додавання `Authorization` заголовка. Вся автентифікація відбувається
  автоматично на рівні браузера через куки.
- **Доменна структура (Domain-Driven)**: Методи згруповані за доменами для
  зручності (напр., `clientApi.auth.login`, `clientApi.user.getProfile`).
- **Складні дані та файли (FormData)**: Для відправки файлів (разом із JSON)
  використовується `FormData`. Логіка її формування виноситься у **приватні
  хелпери** (напр., `buildRegisterFormData`), щоб основні методи API залишалися
  чистими (SOLID).

**Як додавати нові методи:**

1. Опишіть інтерфейс у `types/`.
2. Додайте метод у відповідний домен об'єкта `clientApi`.
